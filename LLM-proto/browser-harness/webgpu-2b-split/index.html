Unzen real two-browser WebGPU split harness

同じ run ID で2つのブラウザ/プロファイルを開きます。 Segment 0 は実 boundary tensors を Coordinator に保存し、Segment 1/standby は Coordinator からのみ取得します。 各ブラウザは自分のsegment専用external weightsだけをSHA-256検証してBrowser Cache APIへ保存します。

role は segment0 / segment1 / standby のexact valueだけを受理します。 明示した worker は Coordinator と同じ ^[A-Za-z0-9._-]{1,128}$ を満たす必要があり、未指定時だけ既存のrandom ID生成を使います。 不正なrole/workerはONNX Runtimeの取得より前に拒否され、trim・型変換・別表現への正規化は行いません。

kvHeads と headSize はURL queryから数値として解釈し、正のsafe integerだけを受理します。 不正値はONNX Runtime、worker登録、manifest/model取得より前に拒否されます。未指定時はそれぞれ 8 と 64 です。 P0 modeではこの一般境界に加えてmodel固有のexact contractも適用されます。

Segment 1/standby の checkpoint 待機には上限があります（既定120秒、checkpointWaitMsで変更可能）。 Stop はfetch/pollを中断します。WebGPU実行中はORT呼び出し自体の強制中断を保証せず、その呼び出しが戻ってsessionを解放するまで「停止要求中」と表示します。
