# Multi-segment output collision preflight

`prepare_budgeted_multi_split()` treats the source ONNX graph and every referenced source external-data file as immutable inputs for the duration of generation. Before any segment graph, segment external-data file, or final `split-manifest.json` is written, every planned destination is checked both for source aliasing and for an unsafe pre-existing destination node.

The source-collision check has two layers. Resolved-path comparison preserves the existing protection against direct path reuse and symlink aliases. For destinations that already exist, filesystem identity comparison with `Path.samefile()` also rejects hard links that resolve to a different pathname but share the same underlying source file. The final `split-manifest.json` destination is part of the same preflight set, so an external-data file named `split-manifest.json` cannot be silently replaced at the end of generation.

A second destination-safety preflight uses `os.lstat()` so it inspects the directory entry itself instead of following it. A destination is allowed when it does not yet exist, or when it is an ordinary pre-existing regular file with exactly one hard link. Pre-existing symlinks, non-regular nodes such as directories/FIFOs/devices, and regular files with multiple hard links are rejected before generation begins. The hard-link rule prevents truncating an unrelated inode through a generated name and also prevents two generated destinations from aliasing the same inode and invalidating an earlier segment hash when a later segment is written.

A collision or unsafe destination is reported before output files are opened for writing. Regression coverage verifies source hard-link and manifest collisions, allows replaceable single-link regular files, and proves that symlink and unrelated hard-link targets retain their bytes when preflight rejects them. Non-regular destinations are rejected as well.

This is a pre-generation overwrite guard, not a general filesystem transaction mechanism. There remains an unavoidable time-of-check/time-of-use window between preflight and later library writes, so callers must prevent concurrent hostile mutation of the output directory while a split run is in progress. The implementation does not claim atomic replacement or directory-level isolation.
