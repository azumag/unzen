# Browser artifact-budget runtime envelope

The real browser split harness treats artifact-budget inputs as runtime data rather than trusting TypeScript or JSON producers. `planSegmentArtifactBudget()` requires a non-array object before it reads segment fields. `verifyActualSegmentArtifactBudget()` requires an object plan and an array of artifact reports before reduction or budget comparisons.

The planner captures only its contract fields (`index`, `browserArtifactBytes`, and `externalData`) from the caller-owned segment, reading each consumed field at most once and preserving fail-fast validation order. In particular, an invalid declared byte count is rejected before the later `externalData` accessor is touched. It deliberately does not spread the whole object, so unrelated enumerable accessors are not executed as a side effect of planning. External-data array membership is detached before any entry `bytes` getter runs, each consumed byte value is captured once, and byte arithmetic uses only the owned primitive snapshot. This prevents an earlier external-data entry from replacing a later array element during the same planning pass.

The verifier takes an owned shallow snapshot of the caller-provided plan before validating or constructing an accepted result. This is important for accessor- or Proxy-backed plans: `declaredBytes`, `requiredMaxBytes`, and `absoluteMaxBytes` must not be read once for validation and then read again with different values while the result is assembled. The captured values are used for both validation and the returned report, so an accepted report describes the same budget state that was actually checked.

Artifact report ownership is also detached before arithmetic. The verifier first snapshots the `reports` array membership, then captures each report's `bytes` field exactly once, and finally performs validation and summation only from those owned primitive values. This prevents an earlier report's `bytes` accessor from replacing a later `reports[]` entry and changing which report participates in the same verification pass. Throwing accessors or Proxy traps during capture still fail closed.

The consumed byte fields must be positive safe integers, the required limit cannot exceed the absolute limit, and declared bytes cannot exceed either runtime limit. Valid plans created by `planSegmentArtifactBudget()` keep the existing P0 (256 MiB) and absolute (1 GiB) behavior. Extra enumerable verifier-plan metadata is preserved in its owned shallow snapshot without re-reading the caller-owned object during result construction.

This contract does not promise recovery from arbitrary throwing Proxy traps during snapshot capture; those failures still fail closed. Issues #662, #666, and #668 remove repeated caller-owned reads across planning, validation, arithmetic, and result construction. They are reliability hardening for #167 and do not provide new real-model artifact-size, physical WebGPU memory, multi-browser relay/latency, or worker-loss evidence.
