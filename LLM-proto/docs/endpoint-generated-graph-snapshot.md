# Endpoint generated-graph snapshot boundary

`tools/prepare_llama_1b_endpoint_preferred_tile_ort_webgpu.py` emits small diagnostic ONNX graphs and records each graph's `bytes` and `sha256` in its generated manifest.

Those two fields come from one read-only descriptor snapshot via `_measure_regular_file()`. The helper rejects symlinks and non-regular inputs, verifies the path identity against the opened descriptor, detects descriptor metadata drift while reading, and rechecks the pathname after the read. It also requests `getattr(os, "O_BINARY", 0)` for the regular-file descriptor so Windows CRT text-mode translation cannot change CRLF or control-like bytes underneath the recorded `st_size` and SHA-256; this flag is a no-op on POSIX. Together these checks keep manifest size and digest bound to the exact persisted graph bytes from one stable snapshot.

For generated graphs that must pass ONNX validation, `_measure_regular_file(path, check_onnx=True)` also retains the exact bytes consumed by that descriptor snapshot and writes them to an exclusive temporary `.onnx` file in the same directory before invoking `onnx.checker.check_model(..., full_check=True)`. The checker therefore validates the same serialized graph bytes whose length and SHA-256 are returned to the manifest, while the same-directory temporary path preserves relative external-data resolution. The temporary graph is removed after validation. Prefix hashing is intentionally incompatible with `check_onnx=True`; checker validation requires a full-file snapshot and rejects a simultaneous `byte_limit` before filesystem I/O.

`_sha256_file()` remains as a compatibility wrapper and returns the digest produced by the same descriptor-pinned primitive. Prefix hashing through `byte_limit` keeps its previous behavior, including unexpected-EOF failure when the requested prefix exceeds the file. The programmatic `byte_limit` contract is explicit: callers may pass only `None` or an exact non-negative Python `int`; `bool`, negative integers, floats (including `NaN` and infinities), strings, and other non-integers are rejected before path expansion or filesystem I/O. Integer `0` continues to mean the empty prefix, positive integers hash exactly that prefix, and `None` hashes the full file.

The preferred 4-way and five-way tile preparers now use the snapshot-bound checker path, so their checker result and recorded graph metadata cannot refer to two different generated graph identities. The post-stage tiled and tiled embedding preparers still reuse `_measure_regular_file()` for raw-byte metadata but retain their earlier pathname-based checker calls; Issue #1167 remains open until those two downstream paths are moved onto the same snapshot-bound checker boundary. Issue #1137 tracks the earlier Windows byte-identity hardening.

This boundary is host-side integrity hardening only. It does not provide new physical WebGPU, browser working-set, multi-browser relay, or worker-loss/resume evidence for Issue #167, and it does not alter the HOLD scope of Issue #158.
