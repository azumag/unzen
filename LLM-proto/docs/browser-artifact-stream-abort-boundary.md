# Browser artifact stream runtime ownership

`readResponseBytesBounded()` treats a supplied `AbortSignal` and Response-like object as caller-owned runtime input. The `aborted` state remains a dynamic read at cancellation boundaries so an abort that races with subscription or a stream pull is still observed.

The established fail-fast ordering remains unchanged: argument and abort validation plus `Content-Length` checks run before normal response-body ownership begins. If one of those checks fails, the function may capture `response.body` once only for best-effort cancellation; a hostile body getter on that cleanup path does not replace the primary validation/cancellation error.

A present `Content-Length` is accepted only in the native `Headers.get()` shape expected at this boundary: `null` means absent, otherwise the value must be a primitive string containing decimal digits only and must parse to a non-negative safe integer. Empty values, whitespace/sign/exponent/hexadecimal/decimal-point spellings, non-string structural values, and oversized integers fail closed before reader acquisition. Diagnostics describe malformed values without invoking caller-defined string or numeric coercion hooks. Leading zeroes remain valid decimal field syntax and are interpreted numerically for the pre-read byte ceiling.

After successful preflight, the response body is captured exactly once. The bounded reader never re-reads `response.body` after that ownership transfer. For stream-backed responses, the accepted body's `getReader` capability is also captured exactly once and invoked with that same body as `this`. This prevents accessor-backed Response/body adapters from presenting one stream during preflight and another during reader acquisition or cleanup. A throwing body/getReader getter or a non-callable `getReader` fails closed before the first reader pull; any already-owned body is cancellation-cleaned best-effort.

After reader acquisition, the required `read` capability is captured once, required to be callable, and invoked with the accepted reader as `this` for every pull. The optional cleanup capabilities `cancel` and `releaseLock` are also sampled once at the same ownership boundary; later abort/error cancellation and lock release use only those captured methods. Cleanup capability getter failures or non-callable values are treated as unavailable cleanup rather than a new primary failure, preserving the existing best-effort cleanup contract. A throwing or non-callable `read` fails closed before signal subscription or the first pull, with pre-ownership cleanup attempted best-effort.

Each value returned by the owned `read` capability must also match the native reader-result shape before EOF is interpreted. The result must be a non-null object and its `done` member must be exactly boolean; truthy/falsy coercion is not accepted. `done` is read and validated before any `value` access. A terminal `done === true` result ends the stream without reading caller-owned `value` at all, while `done === false` reads `value` once and continues to require a real `Uint8Array` chunk. Malformed or throwing non-terminal reader results fail through the same captured cancellation/lock-release path rather than being accepted as silent EOF.

Listener capabilities are owned similarly. Before the reader is acquired, the bounded reader snapshots `addEventListener` and `removeEventListener` exactly once, requires both values to be callable, and then invokes those captured functions with the original signal as `this`. Cleanup always uses the captured remove method rather than performing a fresh property lookup after asynchronous reads.

These ownership rules matter for structural or cross-realm objects whose body, reader, or listener methods can be accessor-backed. A capability that was accepted at the runtime boundary cannot later be replaced with a throwing or unrelated implementation and redirect acquisition, asynchronous pulls, cancellation, cleanup, or strand the artifact reader's abort listener on a long-lived signal.

Reader/body cancellation, listener removal, and reader-lock release remain cleanup operations: cleanup failures must not mask the primary stream validation, cancellation, or successful byte-read outcome. The existing dynamic `aborted` checks before and after reads are unchanged, and the non-stream `arrayBuffer()` fallback remains available when the captured body has no `getReader` capability.

This is browser artifact-stream reliability hardening under #167/#992/#994/#996/#998/#1000/#1002. It does not change artifact budget limits, cache identity, digest verification, model output, deployment, credentials, or production configuration, and it is not new physical WebGPU or multi-browser evidence.
