# Source file snapshot byte contract

`tools/source_file_snapshot.py` is the shared low-level reader used when a source graph or external-data file must be measured or hashed without silently switching filesystem identity.

The helper resolves and pins a regular-file descriptor, compares descriptor metadata before/after reads, verifies that the requested path still resolves to the same file, and rejects bounded reads that exceed the caller's byte ceiling. `hash_file` and `max_bytes` are validated before file I/O. `open_regular_file_snapshot()` exposes the same pinning as a streaming context: it rechecks the requested path before yielding the descriptor-backed stream, so callers can delay all destination creation or digest acceptance until the descriptor and requested pathname are both bound to the same pre-open regular-file identity. On normal exit it checks the descriptor and requested path again.

Snapshot open flags are validated before bitwise construction. `O_RDONLY` is required and must be an integer. `O_BINARY`, `O_CLOEXEC`, `O_NOFOLLOW`, and `O_NONBLOCK` are optional across supported Python/OS combinations: a genuinely absent optional flag contributes nothing, while a present non-integer placeholder is rejected with an intentional runtime error before `os.open()`. This keeps reduced or monkeypatched hosts from leaking raw `TypeError` while preserving the existing portability contract.

On platforms that expose `os.O_BINARY` (notably Windows), the descriptor is opened with that flag. Snapshot size accounting and SHA-256 operate on raw file bytes; newline or control-character translation by a text-mode CRT descriptor is not part of the contract. POSIX behavior is unchanged when `O_BINARY` is absent. Where available, `O_NONBLOCK`, `O_NOFOLLOW`, and `O_CLOEXEC` are also requested before descriptor validation; this makes a last-moment replacement with a FIFO or other special file fail without waiting for a blocking special-file open.

The endpoint payload producer and independent verifier use the streaming snapshot boundary for their source external-data hashing. `tools/materialize_endpoint_payload_chunks.py::materialize_source_payload_chunks()` does not create the payload output directory until the pinned source stream has passed the descriptor and requested-path checks. `tools/verify_endpoint_payload_materialization.py::_sha256_file_and_ranges()` likewise hashes the complete source and selected byte ranges from that one pinned raw-byte stream before accepting source digest/range results. Both retain their existing post-read source signature/path checks, so in-operation mutation or requested-path retargeting still fails closed.

The legacy two-segment generator now uses the same streaming boundary for generated graph digests. `tools/split_llama_1b_onnx.py::sha256_file()` validates `chunk_size` before any snapshot lookup, then hashes `segment*.onnx` from one pinned descriptor in caller-selected chunks. A FIFO/device swap, same-content inode replacement, requested-symlink retarget, descriptor mutation, or path retarget is rejected rather than allowing the manifest SHA-256 to silently bind to a different generated artifact. Existing callers keep the same `sha256_file(path, chunk_size=...)` API and stable files keep the same digest values without introducing a whole-file memory requirement.

The browser P0 source-graph helper now delegates directly to the shared measurement boundary. `tools/prepare_browser_p0.py::sha256_file()` calls `measure_regular_file(path, hash_file=True, label="P0 source graph")` and returns that pinned snapshot digest. This removes the second P0-specific open/stat/read/path-revalidation implementation while preserving the public helper, stable symlink inputs, raw-byte hashing, mutation/path-retarget rejection, and the pinned `SOURCE_GRAPH_SHA256` comparison performed by `verify_pinned_source_graph()`.

The remaining caller-specific snapshot readers follow the same raw-byte rule when they consume payload bytes. `tools/multi_segment_onnx.py::_read_source_graph_snapshot()` and `tools/diagnose_multi_segment_budget.py::_read_source_graph_snapshot()` request `O_BINARY` for bounded source-graph snapshots, and `tools/multi_segment_onnx.py::_measure_source_external_file()` requests it before optional source external-data hashing. The latter keeps `hash_file=False` metadata-only: it still does not read payload bytes. `tools/prepare_budgeted_multi_split_atomic.py::_read_previous_manifest_snapshot()` and `_read_staged_manifest_snapshot()` likewise request `O_BINARY` so publication commit-marker snapshots bind byte counts and validation to the exact on-disk manifest bytes on Windows. Existing best-effort previous-manifest handling, fail-closed staged-manifest handling, path/descriptor identity, symlink-input, mutation, byte-ceiling, and digest contracts remain unchanged.

Reduced-host open-flag regressions live alongside the stable-file, symlink, replacement-race, FIFO, bounded-read, and mutation cases in `tools/tests/test_source_file_snapshot.py`. The browser P0 regression additionally locks `sha256_file()` to the shared `measure_regular_file(..., hash_file=True)` boundary so future P0-specific hashing cannot silently fork again.

This is an integrity/reliability boundary for host-side artifact preparation and verification. It does not provide authenticity against an actor that can rewrite both the source bytes and every higher-level digest/evidence record.
