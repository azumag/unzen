# Serialized Checkpoint Header UTF-8 Integrity

`deserializeCheckpointPayload()` treats the serialized checkpoint header as an input-integrity boundary. Header bytes are decoded with fatal UTF-8 semantics before `JSON.parse()`, so malformed byte sequences cannot be normalized to U+FFFD and then accepted as otherwise-valid checkpoint metadata.

The existing public framing and validation contract remains unchanged: the uint32 header-length prefix, JSON structure checks, metadata validation, payload-length verification, and `serialized checkpoint header must be valid JSON` failure surface are preserved. Outbound headers continue to be generated by `TextEncoder`, so valid checkpoint round trips are unaffected.

This is measurement/frame input-integrity hardening only. It does not authenticate the sender, prove Coordinator transport integrity, provide cryptographic evidence binding, or count as new real-model / physical WebGPU / multi-browser execution evidence.
