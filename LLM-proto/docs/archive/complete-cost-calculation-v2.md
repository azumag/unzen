## 7. 実装上の課題と対策

### 7.1 通信遅延（レイテンシ）

```yaml
課題:
  ノード間通信: 80レイヤー × 平均50ms = 4,000ms（4秒）
  計算時間: 30秒
  合計: 34秒（既存API比10倍の遅延）

対策:
  1. WebRTC P2P通信（Workers経由ではなく直接通信）
  2. 地理的近接ノード優先マッチング
  3. レイヤー数の動的調整（大チャンク優先）
  4. ストリーミング出力（最初のトークンから返却）

目標:
  遅延: 10秒以内（既存API比3倍まで許容）
```

### 7.2 信頼性（ノード離脱）

```yaml
課題:
  ユーザーがタブを閉じる確率: 5%/30秒
  80レイヤー処理中の離脱率: 1 - (0.95^80) ≈ 98%

対策:
  1. 冗長化: 各レイヤーを3ノードで並列処理
  2. 予備ノード: 10%のバッファ確保
  3. チェックポイント: 30レイヤーごとに状態保存
  4. フォールバック: Worker枯渇時は自社サーバー

コスト増:
  冗長化: 3倍の計算コスト
  実効原価: $0.0015 × 3 = $0.0045（DeepSeek比5倍）
  
最適解:
  サンプリング検証: 100回に1回のみ冗長化
  不正検出時のみ該当ノードを冗長化
  実効コスト増: +10%
```
