# ワーカー獲得戦略アイディア集

QJS分散コンピューティングにおけるWorker（計算リソース提供者）をどうやって獲得するかのアイディア集。

## アイディア1: ブラウザ拡張機能モデル

### 概要
エンドユーザーにブラウザ拡張機能をインストールしてもらい、閲覧中にバックグラウンドで計算を実行してもらう。

### ユーザー体験
```
┌──────────────────────────────┐
│ 🖥️ unzen Helper Extension     │
│                              │
│ あなたのブラウザが科学計算に    │
│ 貢献しています                  │
│                              │
│ 今日の貢献: 120回の計算        │
│ 累計報酬: $3.45               │
│                              │
│ 💡 設定                        │
│ • CPU使用率: 30%              │
│ • 実行時間: 閲覧中のみ          │
│                              │
│ [一時停止] [詳細]             │
└──────────────────────────────┘
```

### 報酬モデル
- 仮想通貨でのマイクロペイメント
- Amazonギフト券（$10から換金可能）
- クラウドストレージの無料枠増加
- VPNサービスの無料提供
- ゲーム内通貨

### 利点
- 明示的な同意（オプトイン）
- いつでも停止可能
- 報酬の透明性
- 法的手续きの明確さ

### 課題
- インストール率の低さ
- 報酬の出所（資金が必要）
- マイニング系拡張機能の悪評
- プラットフォーム審査（Chrome Web Store等）

### 実装の鍵
```javascript
// バックグラウンド処理（Service Worker）
chrome.runtime.onMessage.addListener((request) => {
  if (request.type === 'EXECUTE_TASK') {
    // タスクを受信
    const result = await executeInSandbox(request.code, request.input);
    // 結果を返送
    await sendResultToDispatcher(result);
    // 報酬を記録
    await updateRewardBalance(0.01); // $0.01/タスク
  }
});
```

## アイディア2: ゲーミングPC閑散時間活用

### 概要
ゲーマーに対し、プレイしていない時間のGPU/CPUを提供してもらう。

### ターゲット
- 高性能PC所有者
- マイニング経験者（でも電気代が高くて辞めた人）
- 折半モデル（電気代を我慢しても報酬でプラスになる）

### 報酬モデル
- Steamギフトカード
- ゲーム内アイテム
- ハードウェア割引

### 実装
```javascript
// ゲーム検出（プレイ中は停止）
if (isGameRunning()) {
  pauseWorker();
} else if (isIdle()) {
  resumeWorker();
}
```

## アイディア3: 公共施設・図書館モデル

### 概要
図書館、大学、コワーキングスペース等の公共PCを閉館後の時間帯に活用。

### アプローチ
- 施設運営者に「電気代節約」として提案
- 夜間のPC稼働率向上
- 施設への寄付金として還元

### 法的課題
- 公共リソースの私的活用に関する規定
- セキュリティポリシー

## アイディア4: 企業の余剰リソース

### 概要
企業の業務終了後のPC/サーバーを活用。

### ターゲット
- 夜間シャットダウンしていない企業
- データセンターの余剰キャパシティ
- クラウドプロバイダーのスポットインスタンス

### インセンティブ
- コスト削減（電気代を我慢するより収益化）
- ESG/環境貢献の実績
- 税金対策（寄付として処理）

## アイディア5: スマートフォン充電中モデル

### 概要
スマートフォンが充電中かつWi-Fi接続時に計算を実行。

### ターゲット
- スマホ常時充電ユーザー
- 寝ている間の充電
- 職場でのデスク充電

### 報酬
- モバイルデータの無料枠
- アプリ内課金の割引
- ポイント還元

### 課題
- バッテリー劣化の懸念
- 熱問題
- モバイルブラウザの制約

## アイディア6: IoTデバイスモデル

### 概要
常時電源接続のIoTデバイス（スマートスピーカー、TV等）を活用。

### ターゲット
- Raspberry Pi等のシングルボードコンピューター
- 常時稼働のNAS/ルーター
- スマート家電（TV、スピーカー）

### 実装
```bash
# IoTデバイス向け軽量ランタイム
wget https://unzen.dev/install-iot.sh | sh
# → バックグラウンドで常時実行
```

## アイディア8: クラウドクレジット相互交換

### 概要
他のクラウドサービスとのクレジット相互交換。

### 仕組み
```
ユーザーが提供: AWS EC2 10時間
ユーザーが受取: unzen計算 1000回

または逆:
ユーザーが提供: unzen計算 1000回
ユーザーが受取: AWS Lambda 10時間分
```

### メリット
- 資金が不要（物々交換）
- 既存クラウドユーザーへの訴求
- バーター経済の実現

## 選択基準

- ✅ 実装の容易さ

- ✅ 資金要件の低さ

**推奨**: アイディア1（拡張機能）+ 自社プール（最小規模）

- ✅ インセンティブの持続可能性
- ✅ 運営コスト

**推奨**: アイディア4（企業余剰）+ アイディア8（クラウド交換）

### 長期（18ヶ月+）
評価軸:
- ✅ 完全な分散化
- ✅ 自律性
- ✅ エコシステム

**推奨**: アイディア10（ブロックチェーン統合）
