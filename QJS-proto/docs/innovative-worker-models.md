# イノベーティブなWorker獲得モデル

## モデル1: トークン循環経済（Contribute-to-Use）

### 概要
「unzenを提供してトークンを稼ぎ、そのトークンでunzenを利用する」閉じた循環モデル。

### 仕組み
```
ユーザA（サイトオーナー）
   │ ① unzen Workerを設置
   │    ↓ 計算リソース提供
   v
unzenネットワーク
   │ ② トークンを付与（貢献量に応じて）
   v
ユーザA（同じ人）
   │ ③ トークンを使用
   │    ↓ 自分のアプリでunzen利用
   v
unzenネットワーク
   │ ④ 他のユーザーのWorkerが計算
   v
他のサイトオーナー
   │ ⑤ トークンを獲得
   ↓ （循環）
```

### ユースケース例
```javascript
// サイトオーナーAの状況
// 提供: 自分のサイト訪問者10人/日のブラウザ
// 消費: 自分のAPIのデータ処理

// 収支例:
提供した計算: 1000回/月
獲得トークン: 1000 CREDIT

消費した計算: 800回/月（自社API処理）
支払トークン: 800 CREDIT

純収支: +200 CREDIT/月
→ 次月さらに多くの処理が可能
```

### 利点
- **ネット効果**: 提供者が増えるほどサービス品質向上
- **公平性**: 貢献した分だけ利用できる
- **持続可能性**: 外部資金流入不要で循環可能

### 課題
- **初期ブートストラップ**: 誰かが先に提供しないと誰も利用できない
- **法的グレーゾーン**: トークンに金銭価値が生じると規制対象に
- **トークン価値の不安定性**: 需給バランスで価値変動
- **投機**: トレーディング目的の参加者

### 法的対策
```javascript
// トークンを「ポイント」として位置づけ
// → 換金不可、プラットフォーム内のみ有効

規約明記:
"CREDITはunzenプラットフォーム内でのみ使用可能な
 計算クレジットであり、法定通貨への交換はできません。"
```

## モデル2: 自己計算消費（Self-Consuming Compute）★推奨

### 概要
**「自分のサイトの訪問者のブラウザで、自分のサイトの計算処理を実行する」**

### 核心の洞察
```
従来の誤解:
「サイトAの訪問者が、サイトBの計算を手伝う」
→ 訪問者にメリットなし、サイトAにメリットなし

新しいモデル:
「サイトAの訪問者が、サイトAの計算を手伝う」
→ サイトAのサーバーコスト削減
→ 訪問者は「支援している」実感
→ エッジでの処理による高速化
```

### 仕組み
```javascript
// サイトオーナー（自社サイトでunzen設置）

// 1. 訪問者のブラウザで自社データ処理
export async function getRecommendation(userId) {
  // 本来はサーバーサイドで実行
  // → 訪問者のブラウザで分散実行
  
  const recommendations = await unzen.execute({
    code: calculateRecommendations, // 純粋計算
    input: { userId, catalog: cachedCatalog },
    // 訪問者自身のブラウザ（またはプール）で実行
    targetWorkers: 'self-site-pool',
  });
  
  return recommendations;
}
```

### サイトオーナーのインセンティブ

| 従来モデル | 自己計算消費モデル |
|-----------|------------------|
| 外部提供に対して報酬（不明確） | **自社コスト削減（明確）** |
| 訪問者が他社の計算を手伝う | **訪問者が自社サイトを支援** |
| 法的リスク高 | **法的リスク低（自社処理）** |

### 具体的なユースケース

#### 1. レコメンド計算
```javascript
// ECサイトの商品レコメンド
// 本来: サーバーで協調フィルタリング計算
// 変更: 訪問者ブラウザで軽量計算

// ユーザー体験
商品ページ閲覧時（バックグラウンド）:
"このサイトのおすすめを計算中..."
→ サーバーへのAPIコール不要
→ 即座にパーソナライズ結果表示
```

#### 2. 検索・フィルタリング
```javascript
// 大量データのクライアントサイドフィルタ
// 本来: サーバーに検索クエリ送信
// 変更: ブラウザ内でデータ処理

const results = await unzen.execute({
  code: filterAndSort, // 純粋計算
  input: { 
    data: cachedProductList, // 事前ダウンロード済み
    query: userSearchQuery,
  },
});
// サーバー往復なしで即座に結果表示
```

#### 3. リアルタイム分析
```javascript
// ゲームのスコア計算、リーダーボード更新
// 本来: サーバー集中 → ラグ発生
// 変更: プレイヤー間で分散計算

// 各プレイヤーのブラウザが計算に参加
// → サーバー負荷軽減
// → リアルタイム性向上
```

### 訪問者のインセンティブ

```
明示的なオプトインUI:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
💡 このサイトを支援する

このサイトの計算処理を、
あなたのブラウザで少し手伝うことで、
サーバー費用を削減しサイト維持に貢献できます。

[✓] CPU使用率: 10%まで許可
[✓] このセッション中のみ

[支援する] [今はしない]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**訪問者にとってのメリット**:
- 好きなサイトの継続的運営に貢献
- （場合により）プレミアム機能のアンロック
- 広告ブロッカー使用時の代替支援手段

### 技術実装

```javascript
// @unzen/self-consume SDK

// 1. サイトに埋め込み（1行）
import { initSelfCompute } from '@unzen/self-consume';
initSelfCompute({ 
  siteId: 'my-site-123',
  maxCpuPercent: 10,
  consentRequired: true, // GDPR対応
});

// 2. 計算実行（通常の関数呼び出し）
import { compute } from '@unzen/self-consume';

async function getRecommendations(userData) {
  // 自動的に訪問者プールで分散実行
  return await compute(() => {
    // 純粋計算処理
    return collaborativeFilter(userData, productCatalog);
  });
}
```

### 法的手续き（明確化）

```
サイト利用規約に明記:

"本サイトでは、訪問者のブラウザの余剰計算リソースを
使用して、サイト運営に必要な処理（検索結果の整列、
レコメンド計算等）を行う場合があります。

• 処理は明示的な同意後にのみ実行されます
• 個人情報の処理は行われません
• いつでも設定で無効化可能です
• ブラウザのパフォーマンスに影響は最小限です"
```

**法的メリット**:
- 自社データの処理のみ（第三者データなし）
- 明示的な同意（オプトイン）
- データ保護法の適用外（自社処理）

## モデル比較

| 項目 | トークン循環 | 自己計算消費 |
|------|------------|------------|
| **法的リスク** | 中高（トークン規制） | **低（自社処理）** |
| **インセンティブ明確性** | 中（間接的） | **高（コスト削減）** |
| **初期ブートストラップ** | 困難（鶏と卵） | **容易（自社のみ）** |
| **スケーラビリティ** | 高（ネット効果） | 中（サイトごと独立） |
| **資金要件** | 中（トークンシステム） | **低（シンプル）** |
| **実装複雑度** | 高 | **低** |

## ビジョン：「計算の地産地消」

> **「エッジで発生した計算ニーズは、エッジで解決する」**

従来:
```
ユーザーのブラウザ → データセンター → 結果返却
         ↑ 往復のレイテンシとコスト
```

自己計算消費:
```
ユーザーのブラウザ → 同一ブラウザ/近傍で計算 → 即座に表示
         ↑ 地産地消
```

これは:
- **分散コンピューティング**
- **エッジコンピューティング** 
- **サステナブルなWeb**

の実現。
