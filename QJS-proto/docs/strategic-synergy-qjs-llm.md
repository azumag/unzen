# 戦略的シナジー：QJS → LLM の 2段階飛躍モデル

## エグゼクティブサマリー

**Phase 1**: QJS（軽量計算）を**OSSとして無償公開**  
→ 技術的評価・知名度獲得  
→ 分散計算インフラの実証  

**Phase 2**: unzen-LLM（重層計算）で**収益化**  
→ QJSで構築した信頼・インフラを活用  
→ Worker報酬も出しやすい（収益があるため）  
→ モデルレイヤー分割でセキュリティ確保

**本質**: QJSは「入口」、LLMは「収益化」

---

## 1. なぜこの順序か

### 1.1 技術的・ビジネス的論理

```
誤ったアプローチ:
「いきなりLLMから始める」
    ↓
・インフラ未実証（誰もWorkerにならない）
・信頼なし（未知の技術）
・開発コスト巨大（失敗リスク高）

正しいアプローチ:
「QJS → LLM の順序」
    ↓
・インフラ実証済み（動いている実績）
・信頼確立（OSSコミュニティ）
・漸進的成長（段階的投資）
```

### 1.2 2段階の価値創出

| 段階 | 製品 | 戦略 | 目標 |
|------|------|------|------|
| **Phase 1** | QJS | **OSS無償** | 技術的評価・インフラ実証 |
| **Phase 2** | unzen-LLM | **商用** | 収益化・スケーリング |

**シナジー**:
- QJSで構築したWorkerプール → LLMでも流用
- QJSの技術評価 → LLMへの信頼転移
- QJSの知見 → LLMの設計改善

## 3. LLM：収益化エンジンとして

### 3.1 LLMで実現できる収益化

#### ビジネスモデル（LLM版）
```
QJSとの違い:

QJS:
・軽量計算（50ms以内）
・純粋計算のみ
・収益化困難（外部接続禁止）

LLM:
・重層計算（数秒〜数分）
・モデルレイヤー分割（セキュア）
・収益化容易（価値が高い）
```

#### 収益化の具体例
```javascript
// LLM推論APIの価格設定

┌─────────────────────────────────────┐
│ 分散型LLM推論 API                    │
│                                     │
│ • 価格: OpenAI APIの1/5            │
│ • レイテンシ: 追加2-3秒（分散処理） │
│ • プライバシー: モデルレイヤー分割   │
│   → データ漏洩リスク最小           │
│ • 持続可能性: グリーン計算          │
└─────────────────────────────────────┘

価格比較（1Kトークンあたり）:
・OpenAI GPT-4: $0.03
・Claude: $0.02
・unzen-LLM: $0.006（1/5）

コスト構造:
・Worker報酬: $0.003（50%）
・インフラ維持: $0.001（17%）
・運営利益: $0.002（33%）
```

### 3.2 Worker報酬の実現

#### QJSでは困難だった理由
```
QJSでの課題:
・軽量計算 → 単価が低すぎる（$0.000001/回）
・純粋計算 → ユースケースが限定される
・収益なし → 報酬の出所がない
```

#### LLMで解決する理由
```
LLMでのメリット:
・重層計算 → 単価が高い（$0.001/回以上）
・高付加価値 → ユーザーが支払う価値がある
・収益あり → Workerへの報酬が出せる
```

**報酬モデル例**:
```javascript
// Workerへの報酬分配

レイヤー担当Worker:
・1レイヤー（10MB）の計算
・時間: 0.5秒
・報酬: $0.0005

1日の稼働:
・1,000レイヤー計算
・報酬: $0.5/日
・月額: $15/月

→ 個人のインセンティブとして十分
→ 企業の余剰リソース活用として魅力的
```

### 3.3 セキュリティ：モデルレイヤー分割

#### QJSの制約を解決
```
QJSのセキュリティ制約:
「第三者ブラウザに外部接続させると
 踏み台攻撃のリスク」
    ↓
「純粋計算のみ許可」
    ↓
「ユースケースが限定される」

LLMの解決策:
「モデルをレイヤー（10MB）に分割」
    ↓
「各Workerは自分のレイヤーしか見れない」
    ↓
「プロンプト全文は誰も見れない」
    ↓
「踏み台攻撃不可能」
```

#### プライバシー保証
```javascript
// LLM推論のデータフロー

プロンプト: "機密のビジネスプラン..."
    ↓
エントリーノード（レイヤー1）
・受信: 暗号化されたプロンプト
・処理: 第1レイヤーのみ計算
・送信: 中間表現（KVキャッシュ）
    ↓（P2P暗号通信）
中間ノード（レイヤー2〜N-1）
・受信: 中間表現（原文復元不可能）
・処理: 担当レイヤーのみ
    ↓
終端ノード（レイヤーN）
・受信: 最終中間表現
・出力: トークン生成
    ↓
結果返却

**セキュリティ**:
・各Workerは「中間数値」しか見れない
・プロンプト原文を復元するには
  全レイヤーの連携が必要（現実的に不可能）
```

## 4. シナジーの詳細

### 4.1 インフラの再利用

#### Workerプールの共有
```javascript
// QJSで構築したインフラ

QJS Workerプール:
┌─────────┐ ┌─────────┐ ┌─────────┐
│Chrome   │ │Chrome   │ │Chrome   │
│(軽量)   │ │(軽量)   │ │(軽量)   │
│10MB     │ │10MB     │ │10MB     │
└─────────┘ └─────────┘ └─────────┘
    ↓（進化）
    
LLM Workerプール:
┌─────────┐ ┌─────────┐ ┌─────────┐
│Chrome   │ │Chrome   │ │Chrome   │
│(重層)   │ │(重層)   │ │(重層)   │
│10MB×N   │ │10MB×N   │ │10MB×N   │
│WebGPU   │ │WebGPU   │ │WebGPU   │
└─────────┘ └─────────┘ └─────────┘

**同じWorkerが両方に参加可能**:
・軽量時: QJSタスクを処理
```
