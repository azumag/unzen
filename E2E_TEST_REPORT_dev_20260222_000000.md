## Critical Bug Found & Fixed

### BUG-001: Browser bundle bare specifier resolution failure (FIXED)

**Severity**: Critical
**Impact**: Demo page completely non-functional in browser

The client SDK bundle (`index.js`) used bare specifiers (`@unzen/shared`, `vm`) that browsers cannot resolve. This prevented any client-side JavaScript from executing.

**Root Causes**:
1. `@unzen/shared` was externalized in the client bundle (browsers can't resolve bare npm specifiers)
2. `MockSandboxExecutor` imported Node.js `vm` module which is unavailable in browsers
3. `UnzenClient` had a hard dependency on `MockSandboxExecutor` as fallback

**Fix Applied**:
1. Added browser-specific entry point (`src/index.browser.ts`) excluding Node.js-only code
2. Added browser bundle build target (`dist/index.browser.js`) with all deps inlined
3. Demo server now serves the browser bundle instead of the npm bundle
4. `UnzenClient` now requires explicit `workerUrl` or `sandbox` option (no unsafe fallback)

**Tests**: 448 passing (+1 new constructor validation test)

## Key Findings

### Successes
1. All 8 demo functions execute successfully in browser via QuickJS Wasm
2. 4-layer isolation (Web Worker + Wasm + QuickJS + API restrictions) works
3. Manifest caching works correctly (subsequent calls show "cached" badge)
4. No server fallbacks needed - all functions run client-side
5. Performance is good: ~17ms per cached function call

### Issues Found & Fixed
1. **Critical**: Browser bundle had unresolvable bare specifiers (FIXED)
2. **Design**: `UnzenClient` silently used insecure `MockSandboxExecutor` when `workerUrl` was omitted (FIXED - now throws explicit error)

### Test Coverage Gap Identified
- Existing 448 unit/integration tests do NOT cover browser-side execution
- All tests use server-side execution or mocked sandboxes
- This E2E test is the first to verify actual browser execution

---

## Recommendations

1. **Add CI browser tests**: Use Playwright to run E2E tests in CI pipeline
2. **Test server fallback**: Intentionally break a function to verify fallback works
3. **Cross-browser testing**: Test in Firefox and Safari (currently only Chromium tested)
4. **Performance benchmarks**: Track QuickJS Wasm cold start and cached execution times
